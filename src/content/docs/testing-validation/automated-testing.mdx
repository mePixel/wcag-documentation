# Automated Testing

Automated testing tools can quickly identify many common accessibility issues. While they can't catch everything, they're an essential part of any accessibility testing strategy.

## Overview

Automated accessibility testing uses software tools to scan web pages for accessibility issues. These tools can detect about 30-40% of accessibility issues quickly and efficiently.

### Why Automated Testing Matters

- **Speed**: Test entire sites in minutes
- **Consistency**: Same tests run every time
- **CI/CD Integration**: Automate testing in development workflow
- **Early Detection**: Catch issues before they reach production
- **Cost Effective**: Reduce manual testing effort

## Automated Testing Tools

### Browser Extensions

#### axe DevTools

```bash
# Install from Chrome Web Store or Firefox Add-ons
# https://www.deque.com/axe/devtools/
```

**Features:**
- Comprehensive WCAG 2.2 AAA testing
- Detailed issue descriptions
- Code snippets for fixes
- Free and paid versions

**Usage:**
1. Install browser extension
2. Open DevTools
3. Navigate to axe DevTools tab
4. Click "Scan ALL of my page"
5. Review results

#### WAVE

```bash
# Install from Chrome Web Store or Firefox Add-ons
# https://wave.webaim.org/
```

**Features:**
- Visual feedback on page
- Icons indicate issues
- Color contrast checking
- Free to use

**Usage:**
1. Install browser extension
2. Click WAVE icon in toolbar
3. Review icons on page
4. Click icons for details

### Command Line Tools

#### Pa11y

```bash
# Install Pa11y
npm install -g pa11y

# Run Pa11y
pa11y https://example.com

# Run with specific WCAG level
pa11y --standard WCAG2AA https://example.com

# Run with reporter
pa11y --reporter json https://example.com

# Run with threshold
pa11y --threshold 1 https://example.com
```

**Features:**
- Command line interface
- CI/CD integration
- Multiple reporters (JSON, CSV, HTML)
- Configurable rules

#### Lighthouse

```bash
# Install Lighthouse
npm install -g lighthouse

# Run Lighthouse
lighthouse https://example.com --view

# Run with specific categories
lighthouse https://example.com --only-categories=accessibility

# Run with output format
lighthouse https://example.com --output=json --output-path=./report.json
```

**Features:**
- Built into Chrome DevTools
- Performance and accessibility testing
- Detailed reports
- CI/CD integration

### CI/CD Integration

#### GitHub Actions

```yaml
# .github/workflows/accessibility.yml
name: Accessibility Testing

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  accessibility:
    runs-on: ubuntu-latest
    
    steps:
    - uses: actions/checkout@v2
    
    - name: Install Pa11y
      run: npm install -g pa11y
    
    - name: Run Pa11y
      run: pa11y https://example.com --threshold 1
```

#### Jenkins

```groovy
// Jenkinsfile
pipeline {
    agent any
    
    stages {
        stage('Accessibility Testing') {
            steps {
                sh 'npm install -g pa11y'
                sh 'pa11y https://example.com --threshold 1'
            }
        }
    }
}
```

## What Automated Testing Can Detect

### Common Issues Detected

| Issue | WCAG Criterion | Example |
|-------|----------------|---------|
| Missing alt text | 1.1.1 | `<img>` without alt attribute |
| Empty links | 2.4.4 | `<a>` with no text content |
| Empty buttons | 4.1.2 | `<button>` with no text content |
| Missing form labels | 1.3.1 | `<input>` without associated label |
| Low color contrast | 1.4.3 | Text with insufficient contrast |
| Duplicate IDs | 4.1.1 | Multiple elements with same ID |
| Invalid HTML | 4.1.1 | Malformed HTML structure |
| Missing document language | 3.1.1 | `<html>` without lang attribute |

### What Automated Testing Cannot Detect

| Issue | Why Not Detected |
|-------|------------------|
| Alt text quality | Cannot determine if alt text is appropriate |
| Heading structure | Cannot determine logical heading hierarchy |
| Focus order | Cannot determine logical focus flow |
| Keyboard accessibility | Cannot test keyboard navigation |
| Screen reader compatibility | Cannot test with screen readers |
| Context appropriateness | Cannot determine if content is appropriate |
| Dynamic content updates | Cannot detect if updates are announced |

## Implementation Patterns

### Running Automated Tests

```javascript
// Using axe-core
import { AxePuppeteer } from '@axe-core/puppeteer';
import puppeteer from 'puppeteer';

(async () => {
  const browser = await puppeteer.launch();
  const page = await browser.newPage();
  await page.goto('https://example.com');
  
  const results = await new AxePuppeteer(page).analyze();
  console.log(results);
  
  await browser.close();
})();
```

### Custom Rules

```javascript
// Custom axe rule
const customRule = {
  id: 'custom-rule',
  selector: '[data-custom]',
  any: ['custom-check'],
  all: [],
  none: [],
  tags: ['wcag2a', 'wcag2aa'],
  matches: function(node) {
    return node.hasAttribute('data-custom');
  }
};

// Run with custom rules
const results = await new AxePuppeteer(page)
  .withRules(customRule)
  .analyze();
```

### Threshold Testing

```javascript
// Set threshold for number of violations
const results = await new AxePuppeteer(page).analyze();

if (results.violations.length > 0) {
  console.error('Accessibility violations found:', results.violations);
  process.exit(1);
}
```

## Best Practices

### 1. Run Tests Regularly

Integrate automated testing into your development workflow.

```javascript
// Good: Regular testing
// - Run on every commit
// - Run on every pull request
// - Run before deployment
```

### 2. Use Multiple Tools

No single tool catches all issues.

```javascript
// Good: Multiple tools
// - Use axe DevTools for detailed analysis
// - Use WAVE for visual feedback
// - Use Lighthouse for comprehensive testing
// - Use Pa11y for CI/CD integration
```

### 3. Set Appropriate Thresholds

Don't fail builds for minor issues.

```javascript
// Good: Appropriate thresholds
// - Set threshold for critical issues
// - Allow minor issues to be addressed later
// - Prioritize issues by severity
```

### 4. Review Results Manually

Automated tools produce false positives.

```javascript
// Good: Manual review
// - Review all automated results
// - Verify issues are real
// - Determine appropriate fixes
```

### 5. Fix Issues Promptly

Address accessibility issues quickly.

```javascript
// Good: Prompt fixes
// - Fix critical issues immediately
// - Fix major issues soon
// - Fix minor issues in next sprint
```
