# Introduction to WCAG 2.2 AAA

The Web Content Accessibility Guidelines (WCAG) 2.2 is a technical standard developed by the World Wide Web Consortium (W3C) to make web content more accessible to people with disabilities. This guide provides an overview of WCAG 2.2 Level AAA, which is the highest level of web accessibility conformance.

## What is WCAG 2.2?

WCAG 2.2 is an extension of WCAG 2.1, adding 9 new success criteria to address accessibility gaps including focus visibility, dragging movements, target size, and authentication. It maintains backward compatibility with WCAG 2.1 while removing SC 4.1.1 Parsing.

### Key Improvements in WCAG 2.2

- **Focus visibility**: Enhanced focus appearance requirements (SC 2.4.11 Focus Not Obscured, SC 2.4.12 Focus Appearance)
- **Input flexibility**: Dragging movements alternative (SC 2.5.7), larger target sizes (SC 2.5.8)
- **Cognitive accessibility**: Consistent help (SC 3.2.6), redundant entry prevention (SC 3.3.7), accessible authentication without cognitive function tests (SC 3.3.8)
- **Timeouts**: User control over timeouts with advance warning (SC 2.2.6)

## The Four POUR Principles

WCAG is organized around four principles that form the foundation of web accessibility:

### 1. Perceivable

Information and user interface components must be presentable to users in ways they can perceive. This means that users must be able to perceive the information being presented (it can't be invisible to all of their senses).

**Key Requirements:**
- Provide text alternatives for non-text content
- Provide captions and other alternatives for multimedia
- Create content that can be presented in different ways
- Make it easier for users to see and hear content

### 2. Operable

User interface components and navigation must be operable. This means that users must be able to operate the interface (the interface cannot require interaction that a user cannot perform).

**Key Requirements:**
- Make all functionality available from a keyboard
- Give users enough time to read and use content
- Do not design content in a way that is known to cause seizures
- Provide ways to help users navigate, find content, and determine where they are

### 3. Understandable

Information and the operation of user interface must be understandable. This means that users must be able to understand the information as well as the operation of the user interface.

**Key Requirements:**
- Make text content readable and understandable
- Make web pages appear and operate in predictable ways
- Help users avoid and correct mistakes

### 4. Robust

Content must be robust enough that it can be interpreted reliably by a wide variety of user agents, including assistive technologies. This means that users must be able to access the content as technologies advance.

**Key Requirements:**
- Maximize compatibility with current and future user agents, including assistive technologies

## WCAG Conformance Levels

WCAG defines three levels of conformance:

### Level A (Minimum)

The most basic web accessibility features. Meeting Level A requirements means your content is accessible to some users, but many users will still face barriers.

**Examples:**
- Non-text content has text alternatives
- All functionality is available from a keyboard
- Pages have titles that describe topic or purpose

### Level AA (Recommended)

Deals with the biggest and most common accessibility barriers. This is the level most organizations aim for and is often required by law and policy.

**Examples:**
- Color contrast ratio of at least 4.5:1 for normal text
- Text can be resized up to 200% without loss of content
- Focus indicators are visible

### Level AAA (Highest)

The highest and most complex level of web accessibility. Meeting Level AAA requirements is often not possible for all content types and is generally not required by law. However, achieving AAA conformance represents the gold standard for accessibility and provides the most inclusive user experience possible.

**AAA-Specific Success Criteria:**

- **Enhanced contrast (SC 1.4.6)**: Color contrast ratio of at least 7:1 for normal text and 4.5:1 for large text, ensuring readability for users with low vision or color deficiencies
- **Visual presentation (SC 1.4.8)**: Line-height of at least 1.5, paragraph spacing of at least 2em, maximum content width of 80 characters, and no justified text alignment
- **Focus appearance (SC 2.4.12)**: Focus indicator must be at least 2px solid with a 3:1 contrast ratio against adjacent colors and a 1px offset from the focused element
- **Target size (SC 2.5.8)**: All interactive targets must be at least 44×44 CSS pixels, making them easier to activate for users with motor impairments
- **Link purpose (SC 2.4.9)**: The purpose of each link must be determinable from the link text alone, without additional context
- **Reading level (SC 3.1.5)**: Content must be written at a lower secondary education reading level, with supplementary content available for advanced text
- **Accessible authentication (SC 3.3.8)**: No cognitive function tests are required for authentication, with no exceptions — users must never be forced to memorize, transcribe, or solve puzzles to log in
- **Timeout warnings (SC 2.2.6)**: Users must be warned at least 20 seconds in advance before a timeout occurs, with the ability to extend the time limit

## Who Benefits from WCAG Compliance?

WCAG compliance benefits a wide range of users:

### People with Disabilities

- **Visual impairments**: Blindness, low vision, color blindness
- **Hearing impairments**: Deafness, hard of hearing
- **Motor impairments**: Limited mobility, tremors, paralysis
- **Cognitive impairments**: Learning disabilities, attention deficits, memory issues

### Temporary Disabilities

- Broken arm or hand
- Lost glasses
- Ear infection

### Situational Limitations

- Bright sunlight making screens hard to read
- Noisy environment making audio difficult to hear
- Using a mobile device with one hand
- Slow internet connection

### Older Users

- Age-related vision changes
- Reduced motor control
- Cognitive changes

## Legal and Business Considerations

### Legal Requirements

Many countries have laws requiring web accessibility:

- **United States**: Americans with Disabilities Act (ADA), Section 508
- **European Union**: European Accessibility Act
- **Canada**: Accessibility for Ontarians with Disabilities Act (AODA)
- **United Kingdom**: Equality Act 2010
- **Australia**: Disability Discrimination Act 1992

### Business Benefits

- **Larger audience**: 15% of the world's population experiences some form of disability
- **Improved SEO**: Accessible sites often rank better in search engines
- **Better user experience**: Accessibility improvements benefit all users
- **Reduced legal risk**: Compliance reduces the risk of accessibility lawsuits
- **Brand reputation**: Demonstrates commitment to inclusivity

## WCAG 2.2 AAA Success Criteria Overview

WCAG 2.2 includes 87 success criteria across the four principles. Here's a breakdown by principle:

### Perceivable (~21 criteria)

- 1.1 Text Alternatives
- 1.2 Time-based Media
- 1.3 Adaptable
- 1.4 Distinguishable

### Operable (~30 criteria)

- 2.1 Keyboard Accessible
- 2.2 Enough Time
- 2.3 Seizures and Physical Reactions
- 2.4 Navigable
- 2.5 Input Modalities

### Understandable (~18 criteria)

- 3.1 Readable
- 3.2 Predictable
- 3.3 Input Assistance

### Robust (~2 criteria)

- 4.1 Compatible

### New WCAG 2.2 Success Criteria

The following 9 success criteria were added in WCAG 2.2:

- **SC 2.4.11 Focus Not Obscured (AA)**: The focus indicator must not be entirely hidden by author-created content
- **SC 2.4.12 Focus Appearance (AAA)**: Focus indicator must meet enhanced visibility requirements (2px solid, 3:1 contrast, 1px offset)
- **SC 2.4.13 Focus Appearance Minimum (AA)**: Focus indicator must have a minimum area and contrast ratio
- **SC 2.5.7 Dragging Movements (AA)**: All functionality that uses a dragging movement must also be achievable by a single pointer without dragging
- **SC 2.5.8 Target Size Minimum (AA)**: Interactive targets must be at least 24×24 CSS pixels
- **SC 2.5.8 Target Size (AAA)**: Interactive targets must be at least 44×44 CSS pixels
- **SC 3.2.6 Consistent Help (A)**: A mechanism to get help must be available in a consistent location across pages
- **SC 3.3.7 Redundant Entry (A)**: Previously entered information must not be required to be re-entered unless it is essential
- **SC 3.3.8 Accessible Authentication (AAA)**: Authentication must not require cognitive function tests

> **Note:** SC 4.1.1 Parsing (Level A) was removed in WCAG 2.2, as modern browsers and assistive technologies have largely eliminated the parsing issues this criterion addressed.
