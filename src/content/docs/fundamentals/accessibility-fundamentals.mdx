Understanding fundamentals of web accessibility is essential for creating inclusive digital experiences. This guide covers core concepts, principles, and terminology that form the foundation of accessible web development.

## What is Web Accessibility?

Web accessibility means that websites, tools, and technologies are designed and developed so that people with disabilities can use them. More specifically, people can:

- **Perceive** information on screen
- **Understand** information
- **Navigate** through interface
- **Interact** with interface

Accessibility is not just about compliance—it's about ensuring equal access to information and functionality for everyone.

## Core Concepts

### POUR Principles

WCAG is built on four foundational principles, often remembered by the acronym POUR: Perceivable, Operable, Understandable, and Robust.

**Learn more:** [POUR Principles](./pour-principles.mdx)

### Types of Disabilities

Understanding different types of disabilities helps you design for diverse user needs, including visual, hearing, motor, and cognitive disabilities.

**Learn more:** [Types of Disabilities](./disabilities-types.mdx)

### Assistive Technologies

Assistive technologies are tools that help people with disabilities interact with digital content, including screen readers, screen magnifiers, and alternative input devices.

**Learn more:** [Assistive Technologies](./assistive-technologies.mdx)

### Semantic HTML and ARIA

Semantic HTML is the foundation of web accessibility, while ARIA enhances accessibility when HTML alone isn't sufficient.

**Learn more:** [Accessibility Myths and Testing](./accessibility-myths-testing.mdx)

## Quick Start

### 1. Understand POUR Principles

Start by learning the four foundational principles of WCAG:

- **Perceivable**: Information must be presentable to users
- **Operable**: Interface components must be operable
- **Understandable**: Information and operation must be understandable
- **Robust**: Content must be robust enough to work with assistive technologies

**Get started:** [POUR Principles](./pour-principles.mdx)

### 2. Learn About Disabilities

Understand the different types of disabilities and how they affect web accessibility:

- **Visual disabilities**: Blindness, low vision, color blindness
- **Hearing disabilities**: Deafness, hard of hearing
- **Motor disabilities**: Limited mobility, tremors, paralysis
- **Cognitive disabilities**: Learning disabilities, attention deficits, memory issues

**Get started:** [Types of Disabilities](./disabilities-types.mdx)

### 3. Explore Assistive Technologies

Learn about the tools that help users with disabilities access web content:

- **Screen readers**: NVDA, JAWS, VoiceOver, TalkBack
- **Screen magnifiers**: ZoomText, MAGic, built-in magnifiers
- **Alternative input devices**: On-screen keyboards, voice recognition, switch devices
- **Braille displays**: Hardware devices for deaf-blind users

**Get started:** [Assistive Technologies](./assistive-technologies.mdx)

### 4. Understand Semantic HTML and ARIA

Learn about the fundamental technologies for web accessibility:

- **Semantic HTML**: Using appropriate HTML elements for their intended purpose
- **ARIA**: Enhancing accessibility when HTML alone isn't sufficient
- **Common myths**: Debunking common accessibility misconceptions
- **Testing strategies**: Automated, manual, and user testing

**Get started:** [Accessibility Myths and Testing](./accessibility-myths-testing.mdx)

## Key Takeaways

1. **POUR Principles**: Perceivable, Operable, Understandable, Robust form the foundation of WCAG
2. **Diverse Users**: Accessibility benefits people with various disabilities, temporary limitations, and situational constraints
3. **Semantic HTML**: Use appropriate HTML elements to provide meaning and structure
4. **ARIA**: Use ARIA to enhance accessibility when HTML alone isn't sufficient
5. **Testing**: Combine automated, manual, and user testing for comprehensive accessibility
6. **Inclusive Design**: Accessibility is about creating better experiences for everyone
