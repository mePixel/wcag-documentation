This guide provides immediate, actionable steps for implementing the most common and high-impact accessibility features. Each section can be completed in 5-15 minutes and will significantly improve your site's accessibility.

## 1. Add Alt Text to Images (5 minutes)

### Problem
Images without alternative text are invisible to screen reader users, making important content inaccessible.

### Solution
Add descriptive `alt` attributes to all informative images.

```html
<!-- Informative image -->
<img src="chart.png" alt="Bar chart showing 50% increase in sales from 2023 to 2024">

<!-- Decorative image -->
<img src="decoration.png" alt="" role="presentation">

<!-- Image with text -->
<img src="logo.png" alt="Company Logo">
```

### Verification
- Use a screen reader to navigate through images
- Check that each image has appropriate alt text
- Ensure decorative images have empty alt text

## 2. Ensure Keyboard Accessibility (10 minutes)

### Problem
Users who cannot use a mouse rely on keyboard navigation. If interactive elements aren't keyboard accessible, these users cannot use your site.

### Solution
Ensure all interactive elements are focusable and operable via keyboard.

```html
<!-- Make sure all interactive elements are keyboard accessible -->
<button type="button">Submit Form</button>
<a href="/about">About Us</a>
<input type="text" name="email" aria-label="Email address">

<!-- Add visible focus indicators -->
<style>
  button:focus, a:focus, input:focus {
    outline: 3px solid #005fcc;
    outline-offset: 2px;
  }
</style>
```

### Verification
- Press Tab to navigate through the page
- Ensure all interactive elements receive focus
- Verify focus order is logical
- Check that Enter/Space activates buttons and links

## 3. Improve Color Contrast (5 minutes)

### Problem
Low color contrast makes text difficult or impossible to read for users with visual impairments.

### Solution
Ensure text and background colors meet WCAG AA contrast requirements.

```css
/* Good contrast (4.5:1 or higher for normal text) */
body {
  color: #333333;
  background-color: #ffffff;
}

/* Large text can have lower contrast (3:1 or higher) */
h1, h2, h3 {
  color: #444444;
  font-size: 24px;
}

/* Avoid using color alone to convey information */
.error {
  color: #d32f2f;
  font-weight: bold;
}

.success {
  color: #388e3c;
  font-weight: bold;
}
```

### Verification
- Use a color contrast checker tool
- Ensure normal text has at least 4.5:1 contrast ratio
- Ensure large text (18pt+) has at least 3:1 contrast ratio
- Test with grayscale to ensure information is still understandable

## 4. Add Form Labels (5 minutes)

### Problem
Form inputs without labels are confusing and inaccessible, especially for screen reader users.

### Solution
Associate each form input with a descriptive label.

```html
<!-- Explicit labels -->
<form>
  <label for="name">Full Name</label>
  <input type="text" id="name" name="name">
  
  <label for="email">Email Address</label>
  <input type="email" id="email" name="email">
  
  <label for="message">Message</label>
  <textarea id="message" name="message"></textarea>
  
  <button type="submit">Send Message</button>
</form>

<!-- Inline labels -->
<label>
  <input type="checkbox" name="subscribe">
  Subscribe to newsletter
</label>
```

### Verification
- Click on a label and verify the associated input receives focus
- Use a screen reader to navigate the form
- Ensure all inputs have associated labels
- Check that labels are descriptive and clear

## 5. Use Semantic HTML (10 minutes)

### Problem
Using generic `<div>` elements for everything makes content structure unclear to assistive technologies.

### Solution
Use appropriate semantic HTML elements to convey meaning and structure.

```html
<!-- Use semantic elements instead of divs -->
<header>
  <nav>
    <ul>
      <li><a href="/">Home</a></li>
      <li><a href="/about">About</a></li>
      <li><a href="/contact">Contact</a></li>
    </ul>
  </nav>
</header>

<main>
  <article>
    <h1>Article Title</h1>
    <p>Article content goes here...</p>
  </article>
  
  <aside>
    <h2>Related Links</h2>
    <ul>
      <li><a href="/link1">Related 1</a></li>
      <li><a href="/link2">Related 2</a></li>
    </ul>
  </aside>
</main>

<footer>
  <p>&copy; 2024 Company Name</p>
</footer>
```

### Verification
- Use a screen reader to navigate by landmarks
- Check that heading levels are properly nested (h1, h2, h3, etc.)
- Verify lists are marked up as `<ul>` or `<ol>`
- Ensure navigation is in a `<nav>` element

## 6. Add Page Titles (2 minutes)

### Problem
Pages without descriptive titles make it difficult for users to understand where they are, especially screen reader users.

### Solution
Add unique, descriptive titles to each page.

```html
<head>
  <title>About Us - Company Name</title>
</head>
```

### Verification
- Check that each page has a unique title
- Ensure titles are descriptive and meaningful
- Verify titles appear in browser tabs
- Test with screen reader to hear page title announced

## 7. Provide Skip Links (5 minutes)

### Problem
Users navigating by keyboard must tab through all navigation links to reach main content, which is frustrating and time-consuming.

### Solution
Add a skip link that allows keyboard users to jump directly to main content.

```html
<body>
  <a href="#main-content" class="skip-link">
    Skip to main content
  </a>
  
  <header>
    <!-- Navigation content -->
  </header>
  
  <main id="main-content">
    <!-- Main content -->
  </main>
</body>

<style>
  .skip-link {
    position: absolute;
    top: -40px;
    left: 0;
    background: #000;
    color: #fff;
    padding: 8px;
    z-index: 100;
  }
  
  .skip-link:focus {
    top: 0;
  }
</style>
```

### Verification
- Press Tab when page loads
- Verify skip link appears and is focusable
- Press Enter to activate skip link
- Ensure focus moves to main content

## 8. Make Links Descriptive (5 minutes)

### Problem
Links like "click here" or "read more" provide no context about the destination, especially for screen reader users who navigate by links.

### Solution
Use descriptive link text that indicates the destination or purpose.

```html
<!-- Bad -->
<a href="/about">Click here</a> to learn about our company.
<a href="/article">Read more</a>

<!-- Good -->
<a href="/about">Learn about our company</a>
<a href="/article">Read the full article about accessibility</a>

<!-- For icon links, add aria-label -->
<a href="/settings" aria-label="Settings">
  <svg aria-hidden="true">...</svg>
</a>
```

### Verification
- Read links out of context to ensure they make sense
- Use screen reader link navigation to test
- Ensure link text is unique when pointing to different destinations
- Check that icon-only links have aria-label

## Common Mistakes to Avoid

- **Adding alt text to decorative images**: Use empty alt text (`alt=""`) instead
- **Using color alone to convey information**: Always provide additional indicators
- **Hiding focus indicators**: Keep them visible for keyboard users
- **Using placeholder text as labels**: Always use proper `<label>` elements
- **Skipping heading levels**: Maintain proper heading hierarchy (h1 → h2 → h3)
