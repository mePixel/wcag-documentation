# POUR Principles

WCAG is built on four foundational principles, often remembered by the acronym POUR: Perceivable, Operable, Understandable, and Robust. These principles form the foundation of accessible web development.

## What is Web Accessibility?

Web accessibility means that websites, tools, and technologies are designed and developed so that people with disabilities can use them. More specifically, people can:

- **Perceive** information on screen
- **Understand** information
- **Navigate** through interface
- **Interact** with interface

Accessibility is not just about compliance—it's about ensuring equal access to information and functionality for everyone.

## Perceivable

Information and user interface components must be presentable to users in ways they can perceive. This means users must be able to perceive the information being presented.

### Key Concepts

**Text Alternatives**: Provide text alternatives for any non-text content so that it can be changed into other forms people need, such as large print, braille, speech, symbols, or simpler language.

**Time-based Media**: Provide alternatives for time-based media.

**Adaptable**: Create content that can be presented in different ways without losing information or structure.

**Distinguishable**: Make it easier for users to see and hear content, including separating foreground from background.

### Examples

- Adding `alt` text to images
- Providing captions for videos
- Ensuring sufficient color contrast
- Allowing text to be resized

### WCAG Success Criteria

The Perceivable principle includes guidelines 1.1 through 1.4:

- **1.1 Text Alternatives**: Provide text alternatives for non-text content
- **1.2 Time-based Media**: Provide alternatives for time-based media
- **1.3 Adaptable**: Create content that can be presented in different ways
- **1.4 Distinguishable**: Make it easier to see and hear content

### Why It Matters

Users with visual impairments may not be able to see images or videos. Users with hearing impairments may not be able to hear audio. Providing alternatives ensures all users can access the information.

## Operable

User interface components and navigation must be operable. This means users must be able to operate the interface.

### Key Concepts

**Keyboard Accessible**: Make all functionality available from a keyboard.

**Enough Time**: Provide users enough time to read and use content.

**Seizures and Physical Reactions**: Do not design content in a way that is known to cause seizures or physical reactions.

**Navigable**: Provide ways to help users navigate, find content, and determine where they are.

### Examples

- Ensuring all interactive elements can be accessed via keyboard
- Providing pause/stop controls for moving content
- Including skip links to bypass navigation
- Maintaining logical tab order

### WCAG Success Criteria

The Operable principle includes guidelines 2.1 through 2.5:

- **2.1 Keyboard Accessible**: Make all functionality available from a keyboard
- **2.2 Enough Time**: Provide users enough time to read and use content
- **2.3 Seizures and Physical Reactions**: Do not design content that causes seizures
- **2.4 Navigable**: Provide ways to help users navigate
- **2.5 Input Modalities**: Make functionality available from various input devices

### Why It Matters

Users with motor disabilities may not be able to use a mouse. Users with cognitive disabilities may need more time to complete tasks. Keyboard accessibility and sufficient time ensure all users can interact with your content.

## Understandable

Information and operation of user interface must be understandable. This means users must be able to understand the information and interface.

### Key Concepts

**Readable**: Make text content readable and understandable.

**Predictable**: Make web pages appear and operate in predictable ways.

**Input Assistance**: Help users avoid and correct mistakes.

### Examples

- Using clear, simple language
- Maintaining consistent navigation
- Providing helpful error messages
- Offering form validation and suggestions

### WCAG Success Criteria

The Understandable principle includes guidelines 3.1 through 3.3:

- **3.1 Readable**: Make text content readable and understandable
- **3.2 Predictable**: Make web pages appear and operate in predictable ways
- **3.3 Input Assistance**: Help users avoid and correct mistakes

### Why It Matters

Users with cognitive disabilities may have difficulty understanding complex language or unpredictable interfaces. Clear language, consistent navigation, and helpful error messages ensure all users can understand and use your content.

## Robust

Content must be robust enough that it can be interpreted reliably by a wide variety of user agents, including assistive technologies. This means users must be able to access the content as technologies advance.

### Key Concepts

**Compatible**: Maximize compatibility with current and future user agents, including assistive technologies.

### Examples

- Using valid HTML
- Properly using ARIA attributes
- Ensuring proper name, role, and value for custom components
- Testing with multiple browsers and assistive technologies

### WCAG Success Criteria

The Robust principle includes guideline 4.1:

- **4.1 Compatible**: Maximize compatibility with current and future user agents

### Why It Matters

Assistive technologies rely on properly structured content to interpret and present information to users. Valid HTML and proper ARIA usage ensure your content works with current and future assistive technologies.

## Applying POUR Principles

### Design Phase

Consider POUR principles from the beginning of your design process:

- **Perceivable**: Ensure all information is available in multiple formats
- **Operable**: Design for keyboard and alternative input methods
- **Understandable**: Use clear language and consistent patterns
- **Robust**: Use semantic HTML and proper ARIA

### Development Phase

Implement POUR principles during development:

- **Perceivable**: Add alt text, captions, and ensure color contrast
- **Operable**: Test keyboard navigation and provide sufficient time
- **Understandable**: Write clear content and provide helpful error messages
- **Robust**: Use valid HTML and test with assistive technologies

### Testing Phase

Verify POUR principles through testing:

- **Perceivable**: Test with screen readers and screen magnifiers
- **Operable**: Test keyboard navigation and alternative input devices
- **Understandable**: Test with users who have cognitive disabilities
- **Robust**: Test with multiple browsers and assistive technologies

## Key Takeaways

1. **Foundation**: POUR principles form the foundation of WCAG 2.1
2. **Interconnected**: All four principles work together to create accessible experiences
3. **User-Centered**: Each principle addresses specific user needs
4. **Holistic Approach**: Apply all principles, not just one or two
5. **Continuous Process**: Accessibility is an ongoing process, not a one-time task
