# 1.3 Adaptable

## 1.3.1 Info and Relationships (Level A)

### Requirement

Information, structure, and relationships conveyed through presentation can be programmatically determined or are available in text.

### Understanding

The structure and relationships of content must be available to assistive technologies through semantic HTML or ARIA attributes.

### Sufficient Techniques

- **H42**: Using h1-h6 to identify headings
- **H48**: Using ol, ul, and dl for lists
- **H51**: Using table markup to present tabular information
- **H73**: Using the summary attribute of the table element to give an overview of data tables

### Example

```html
<!-- Proper heading structure -->
<h1>Main Title</h1>
<h2>Section Title</h2>
<h3>Subsection Title</h3>

<!-- Proper list structure -->
<ul>
  <li>Item 1</li>
  <li>Item 2</li>
</ul>

<!-- Proper table structure -->
<table>
  <caption>Monthly Sales Data</caption>
  <thead>
    <tr>
      <th>Month</th>
      <th>Sales</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>January</td>
      <td>$10,000</td>
    </tr>
  </tbody>
</table>
```

## 1.3.2 Meaningful Sequence (Level A)

### Requirement

When the sequence in which content is presented affects its meaning, a correct reading sequence can be programmatically determined.

### Understanding

The order in which content is presented must match the logical reading order, especially for screen reader users.

### Sufficient Techniques

- **H57**: Using language attributes on the html element
- **H34**: Using a Unicode right-to-left mark

## 1.3.3 Sensory Characteristics (Level A)

### Requirement

Instructions provided for understanding and operating content do not rely solely on sensory characteristics of components such as shape, size, visual location, orientation, or sound.

### Understanding

Instructions must not rely solely on visual or auditory characteristics. Provide multiple ways to identify elements.

### Example

```html
<!-- Bad: Relies on visual position -->
"Click the button on the right"

<!-- Good: Provides multiple identifiers -->
"Click the 'Submit' button on the right side of the form"
```

## 1.3.4 Orientation (Level AA)

### Requirement

Content does not restrict its view and operation to a single display orientation, such as portrait or landscape, unless a specific display orientation is essential.

### Understanding

Users should be able to view and interact with content in both portrait and landscape orientations.

### Sufficient Techniques

- **G208**: Ensuring that content does not trap keyboard focus

## 1.3.5 Identify Input Purpose (Level AA)

### Requirement

The purpose of each input field collecting information about the user can be programmatically determined when the input field serves a purpose identified in the Input Purposes for User Interface Components section.

### Understanding

Form fields should have programmatically determinable purposes to help users understand what information is being requested.

### Sufficient Techniques

- **G181**: Providing a mechanism for the user to find the desired heading
- **H44**: Using label elements to associate text labels with form controls

### Example

```html
<label for="email">Email Address</label>
<input type="email" id="email" name="email" autocomplete="email">
```
