# Predictable Success Criteria

Web pages must appear and operate in predictable ways. This means that users must be able to determine the consequences of their actions and navigate the interface consistently.

## Overview

The Predictable guideline includes 4 success criteria across Level A and AA:

- **Level A**: 2 criteria
- **Level AA**: 2 criteria

## 3.2.1 On Focus (Level A)

**Requirement**: When any component receives focus, it does not initiate a change of context.

**Understanding**: Elements should not change context when they receive focus. This can disorient users, especially those using screen readers.

**Sufficient Techniques**:
- **G200**: Providing a way to pause, stop, or hide content that moves, blinks, or auto-updates

**Example**:
```html
<!-- Bad: Changes context on focus -->
<input type="text" onfocus="window.location.href='/new-page'">

<!-- Good: No context change on focus -->
<input type="text" onfocus="showHelpText()">

<!-- Bad: Opens dropdown on focus -->
<div tabindex="0" onfocus="openDropdown()">
  Menu
</div>

<!-- Good: Requires click to open -->
<button onclick="openDropdown()">
  Menu
</button>
```

### Common Mistakes

```html
<!-- Bad: Navigation on focus -->
<a href="/page" onfocus="window.location.href='/page'">Link</a>

<!-- Good: Navigation on click -->
<a href="/page">Link</a>

<!-- Bad: Opens modal on focus -->
<button onfocus="openModal()">Open Modal</button>

<!-- Good: Opens modal on click -->
<button onclick="openModal()">Open Modal</button>
```

## 3.2.2 On Input (Level A)

**Requirement**: Changing the setting of any user interface component does not automatically cause a change of context unless the user has been advised of the behavior before using the component.

**Understanding**: Form inputs should not automatically submit or change context when the user enters data, unless this is clearly communicated.

**Sufficient Techniques**:
- **G201**: Giving users control over when audio starts

**Example**:
```html
<!-- Bad: Auto-submits on input -->
<input type="text" name="search" oninput="submitForm()">

<!-- Good: Requires explicit action -->
<form onsubmit="submitForm()">
  <input type="text" name="search">
  <button type="submit">Search</button>
</form>

<!-- Bad: Changes page on selection -->
<select onchange="window.location.href=this.value">
  <option value="/page1">Page 1</option>
  <option value="/page2">Page 2</option>
</select>

<!-- Good: Requires explicit action -->
<select id="pageSelect">
  <option value="/page1">Page 1</option>
  <option value="/page2">Page 2</option>
</select>
<button onclick="goToPage()">Go</button>
```

### Common Mistakes

```html
<!-- Bad: Auto-submit on input -->
<input type="text" oninput="submitForm()">

<!-- Good: Explicit submit button -->
<form onsubmit="submitForm()">
  <input type="text">
  <button type="submit">Submit</button>
</form>

<!-- Bad: Auto-navigation on select -->
<select onchange="navigate()">
  <option value="/page1">Page 1</option>
</select>

<!-- Good: Explicit navigation -->
<select id="pageSelect">
  <option value="/page1">Page 1</option>
</select>
<button onclick="navigate()">Go</button>
```

## 3.2.3 Consistent Navigation (Level AA)

**Requirement**: Navigational mechanisms that are repeated on multiple Web pages within a set of Web pages occur in the same relative order each time they appear, unless a change is initiated by the user.

**Understanding**: Navigation should be consistent across pages to help users predict where to find elements.

**Sufficient Techniques**:
- **G61**: Presenting repeated components in the same relative order each time they appear

**Example**:
```html
<!-- Good: Consistent navigation across pages -->
<!-- Page 1 -->
<header>
  <nav>
    <ul>
      <li><a href="/">Home</a></li>
      <li><a href="/about">About</a></li>
      <li><a href="/products">Products</a></li>
      <li><a href="/contact">Contact</a></li>
    </ul>
  </nav>
</header>

<!-- Page 2 - Same order -->
<header>
  <nav>
    <ul>
      <li><a href="/">Home</a></li>
      <li><a href="/about">About</a></li>
      <li><a href="/products">Products</a></li>
      <li><a href="/contact">Contact</a></li>
    </ul>
  </nav>
</header>
```

### Common Mistakes

```html
<!-- Bad: Inconsistent navigation order -->
<!-- Page 1 -->
<nav>
  <ul>
    <li><a href="/">Home</a></li>
    <li><a href="/about">About</a></li>
    <li><a href="/contact">Contact</a></li>
  </ul>
</nav>

<!-- Page 2 - Different order -->
<nav>
  <ul>
    <li><a href="/contact">Contact</a></li>
    <li><a href="/">Home</a></li>
    <li><a href="/about">About</a></li>
  </ul>
</nav>
```

## 3.2.4 Consistent Identification (Level AA)

**Requirement**: Components that have the same functionality within a set of Web pages are identified consistently.

**Understanding**: Elements with the same function should have consistent labels and identifiers across pages.

**Sufficient Techniques**:
- **G197**: Using labels, names, and text alternatives consistently for content that has the same functionality

**Example**:
```html
<!-- Good: Consistent identification across pages -->
<!-- Page 1 -->
<button type="submit">Submit Form</button>
<a href="/help" aria-label="Get help">Help</a>

<!-- Page 2 - Same labels -->
<button type="submit">Submit Form</button>
<a href="/help" aria-label="Get help">Help</a>

<!-- Bad: Inconsistent identification -->
<!-- Page 1 -->
<button type="submit">Submit Form</button>

<!-- Page 2 -->
<button type="submit">Send</button>
```

### Common Mistakes

```html
<!-- Bad: Inconsistent button labels -->
<!-- Page 1 -->
<button type="submit">Submit Form</button>

<!-- Page 2 -->
<button type="submit">Send</button>

<!-- Page 3 -->
<button type="submit">Continue</button>

<!-- Good: Consistent button labels -->
<!-- All pages -->
<button type="submit">Submit Form</button>
```

## Testing Checklist

### Visual Testing
- [ ] Navigation is consistent across pages
- [ ] Elements with same function have consistent labels
- [ ] Focus doesn't change context unexpectedly
- [ ] Input doesn't change context unexpectedly

### Screen Reader Testing
- [ ] Navigation order is consistent
- [ ] Element labels are consistent
- [ ] Focus changes are announced appropriately
- [ ] Context changes are announced

### Keyboard Testing
- [ ] Focus doesn't trigger unexpected actions
- [ ] Input doesn't trigger unexpected actions
- [ ] Navigation order is predictable
- [ ] Can navigate consistently across pages

### Functional Testing
- [ ] Focus behavior is predictable
- [ ] Input behavior is predictable
- [ ] Navigation is consistent
- [ ] Element identification is consistent

## Best Practices

### 1. Don't Change Context on Focus

Avoid actions that change context when elements receive focus.

```html
<!-- Bad: Changes context on focus -->
<input type="text" onfocus="window.location.href='/new-page'">

<!-- Good: No context change on focus -->
<input type="text" onfocus="showHelpText()">
```

### 2. Don't Auto-Submit on Input

Require explicit user action to submit forms.

```html
<!-- Bad: Auto-submits on input -->
<input type="text" oninput="submitForm()">

<!-- Good: Requires explicit action -->
<form onsubmit="submitForm()">
  <input type="text">
  <button type="submit">Submit</button>
</form>
```

### 3. Maintain Consistent Navigation

Keep navigation in the same order across pages.

```html
<!-- All pages -->
<nav>
  <ul>
    <li><a href="/">Home</a></li>
    <li><a href="/about">About</a></li>
    <li><a href="/products">Products</a></li>
    <li><a href="/contact">Contact</a></li>
  </ul>
</nav>
```

### 4. Use Consistent Labels

Use the same labels for elements with the same function.

```html
<!-- All pages -->
<button type="submit">Submit Form</button>
<a href="/help" aria-label="Get help">Help</a>
```
