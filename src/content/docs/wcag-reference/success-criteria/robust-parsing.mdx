# 4.1.1 Parsing (Level A)

## Requirement

In content implemented using markup languages, elements have complete start and end tags, elements are nested according to their specifications, elements do not contain duplicate attributes, and any IDs are unique, except where the specifications allow these features.

## Understanding

Valid HTML ensures that assistive technologies can correctly parse and interpret the content structure. Invalid markup can cause accessibility issues.

## Sufficient Techniques

- **H74**: Ensuring that opening and closing tags are used according to specification
- **H88**: Using HTML according to spec
- **H93**: Ensuring that id attributes are unique on a Web page

## Examples

### Good: Valid HTML

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Valid HTML Page</title>
</head>
<body>
  <header>
    <nav>
      <ul>
        <li><a href="/">Home</a></li>
        <li><a href="/about">About</a></li>
      </ul>
    </nav>
  </header>
  
  <main>
    <h1>Page Title</h1>
    <p>Content goes here.</p>
  </main>
  
  <footer>
    <p>&copy; 2024 Company</p>
  </footer>
</body>
</html>
```

### Bad: Invalid HTML

```html
<!-- Unclosed paragraph -->
<div>
  <p>Unclosed paragraph
  <div>Nested incorrectly</div>
</div>

<!-- Duplicate IDs -->
<div id="main">Content 1</div>
<div id="main">Content 2</div>

<!-- Duplicate attributes -->
<input type="text" type="email" name="email">
```

## Common Failures

- **F70**: Failure of Success Criterion 4.1.1 due to duplicate values of type attributes
- **F71**: Failure of Success Criterion 4.1.1 due to duplicate values of id attributes
- **F77**: Failure of Success Criterion 4.1.1 due to missing start or end tags

## Best Practices

1. **Use proper DOCTYPE declaration** - Always include `<!DOCTYPE html>` at the start of your document
2. **Close all tags properly** - Ensure every opening tag has a corresponding closing tag
3. **Nest elements correctly** - Follow HTML specification for element nesting
4. **Avoid duplicate attributes** - Each element should have unique attributes
5. **Ensure unique IDs** - Use unique IDs for elements that need them

## Testing Checklist

- [ ] Validate HTML using W3C Markup Validation Service
- [ ] Check for unclosed tags
- [ ] Verify proper element nesting
- [ ] Ensure all IDs are unique
- [ ] Check for duplicate attributes
- [ ] Test with screen readers to ensure proper parsing
