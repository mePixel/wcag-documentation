# Understandable Success Criteria

Information and operation of user interface must be understandable. This means that users must be able to understand information as well as operation of user interface.

## Overview

The Understandable principle includes 10 success criteria across Level A, AA, and AAA:

- **Level A**: 3 criteria
- **Level AA**: 6 criteria
- **Level AAA**: 3 criteria

This reference focuses on Level A and AA criteria that are most commonly required.

## Guideline Sections

### [Readable Criteria](./readable-criteria.mdx)

Information and user interface components must be readable. This means that users must be able to understand the information presented to them.

**Criteria Covered:**
- **3.1.1 Language of Page (Level A)**: The default human language of each Web page can be programmatically determined
- **3.1.2 Language of Parts (Level AA)**: The human language of each passage or phrase in content can be programmatically determined

**When to use:**
- When setting up page language
- When content includes multiple languages
- When ensuring proper pronunciation for screen readers

### [Predictable Criteria](./predictable-criteria.mdx)

Web pages must appear and operate in predictable ways. This means that users must be able to determine the consequences of their actions and navigate the interface consistently.

**Criteria Covered:**
- **3.2.1 On Focus (Level A)**: When any component receives focus, it does not initiate a change of context
- **3.2.2 On Input (Level A)**: Changing the setting of any user interface component does not automatically cause a change of context unless the user has been advised of the behavior before using the component
- **3.2.3 Consistent Navigation (Level AA)**: Navigational mechanisms that are repeated on multiple Web pages within a set of Web pages occur in the same relative order each time they appear, unless a change is initiated by the user
- **3.2.4 Consistent Identification (Level AA)**: Components that have the same functionality within a set of Web pages are identified consistently

**When to use:**
- When designing focus behavior
- When implementing form inputs
- When creating navigation systems
- When ensuring consistent UI patterns

### [Input Assistance Criteria](./input-assistance-criteria.mdx)

Help users avoid and correct mistakes. This means that users must be able to understand and correct input errors.

**Criteria Covered:**
- **3.3.1 Error Identification (Level A)**: If an input error is automatically detected, the item that is in error is identified and the error is described to the user in text
- **3.3.2 Labels or Instructions (Level A)**: Labels or instructions are provided when content requires user input
- **3.3.3 Error Suggestion (Level AA)**: If an input error is automatically detected and suggestions for correction are known, then the suggestions are provided to the user, unless it would jeopardize the security or purpose of the content
- **3.3.4 Error Prevention (Legal, Financial, Data) (Level AA)**: For Web pages that cause legal commitments or financial transactions for the user, that modify or delete user-controllable data in data storage systems, or that submit user test responses, at least one of the following is true

**When to use:**
- When creating forms
- When implementing validation
- When designing error messages
- When handling critical actions

## Testing Checklist

### Visual Testing
- [ ] Language is correctly set on html element
- [ ] Language changes are visually indicated (if applicable)
- [ ] Navigation is consistent across pages
- [ ] Elements with same function have consistent labels
- [ ] Focus doesn't change context unexpectedly
- [ ] Input doesn't change context unexpectedly
- [ ] Errors are clearly identified
- [ ] Error messages are specific and helpful
- [ ] Labels are present for all inputs
- [ ] Confirmation is provided for critical actions

### Screen Reader Testing
- [ ] Page language is announced correctly
- [ ] Language changes are announced
- [ ] Pronunciation is correct for each language
- [ ] Navigation order is consistent
- [ ] Element labels are consistent
- [ ] Focus changes are announced appropriately
- [ ] Context changes are announced
- [ ] Error messages are announced
- [ ] Error messages are associated with fields
- [ ] Labels are announced
- [ ] Instructions are announced
- [ ] Confirmation dialogs are announced

### Keyboard Testing
- [ ] Focus doesn't trigger unexpected actions
- [ ] Input doesn't trigger unexpected actions
- [ ] Navigation order is predictable
- [ ] Can navigate consistently across pages
- [ ] Can navigate to error fields
- [ ] Can correct errors
- [ ] Can confirm or cancel actions
- [ ] Can reverse actions when available

### Functional Testing
- [ ] Focus behavior is predictable
- [ ] Input behavior is predictable
- [ ] Navigation is consistent
- [ ] Element identification is consistent
- [ ] Error identification works correctly
- [ ] Error suggestions are helpful
- [ ] Labels are properly associated
- [ ] Confirmation prevents accidental actions
- [ ] Reversible actions work correctly

## Best Practices

### 1. Always Set Language Attribute

Set the language attribute on the html element.

```html
<html lang="en">
  <!-- Page content -->
</html>
```

### 2. Don't Change Context on Focus

Avoid actions that change context when elements receive focus.

```html
<!-- Bad: Changes context on focus -->
<input type="text" onfocus="window.location.href='/new-page'">

<!-- Good: No context change on focus -->
<input type="text" onfocus="showHelpText()">
```

### 3. Don't Auto-Submit on Input

Require explicit user action to submit forms.

```html
<!-- Bad: Auto-submits on input -->
<input type="text" oninput="submitForm()">

<!-- Good: Requires explicit action -->
<form onsubmit="submitForm()">
  <input type="text">
  <button type="submit">Submit</button>
</form>
```

### 4. Maintain Consistent Navigation

Keep navigation in the same order across pages.

```html
<!-- All pages -->
<nav>
  <ul>
    <li><a href="/">Home</a></li>
    <li><a href="/about">About</a></li>
    <li><a href="/products">Products</a></li>
    <li><a href="/contact">Contact</a></li>
  </ul>
</nav>
```

### 5. Use Consistent Labels

Use the same labels for elements with the same function.

```html
<!-- All pages -->
<button type="submit">Submit Form</button>
<a href="/help" aria-label="Get help">Help</a>
```

### 6. Identify Errors Clearly

Use `aria-invalid` and `aria-describedby` to identify errors.

```html
<input type="email" id="email" aria-invalid="true" aria-describedby="email-error">
<span id="email-error" class="error">Please enter a valid email address</span>
```

### 7. Provide Descriptive Labels

Use proper labels for all form inputs.

```html
<label for="name">Full Name</label>
<input type="text" id="name" name="name">
```

### 8. Offer Error Suggestions

Provide helpful suggestions for correcting errors.

```javascript
emailError.textContent = 'Please enter a valid email address (e.g., user@example.com)';
```

### 9. Provide Confirmation for Critical Actions

Allow users to review and confirm critical actions.

```html
<button onclick="showConfirmation()">Delete Account</button>
```

### 10. Allow Reversal When Possible

Provide ways to reverse actions when appropriate.

```html
<button onclick="deleteItem()">Delete Item</button>
<button onclick="undoDelete()">Undo Delete</button>
```
