# Forms Techniques

Accessible forms ensure all users can understand, complete, and submit form data regardless of their abilities.

## Form Labels

**Technique**: H44 - Using label elements to associate text labels with form controls

Associate each form input with a descriptive label.

```html
<form>
  <label for="name">Full Name</label>
  <input type="text" id="name" name="name">
  
  <label for="email">Email Address</label>
  <input type="email" id="email" name="email">
  
  <label for="message">Message</label>
  <textarea id="message" name="message"></textarea>
  
  <button type="submit">Submit</button>
</form>
```

**Related Criteria**: 1.3.1 Info and Relationships, 3.3.2 Labels or Instructions

**Best Practices:**
- Always use `<label>` element with `for` attribute
- Match `for` attribute value with input's `id` attribute
- Place labels before or above their associated controls
- Use fieldset and legend for related groups

## Required Fields

**Technique**: H90 - Indicating required form controls using required attribute

Mark required form fields programmatically.

```html
<label for="email">Email Address *</label>
<input type="email" id="email" name="email" required aria-required="true">
```

**Related Criteria**: 3.3.2 Labels or Instructions

**Best Practices:**
- Use both `required` attribute and visual indicator (*)
- Use `aria-required="true"` for additional clarity
- Group related required fields together
- Provide clear instructions about required fields

## Form Validation

**Technique**: G84 - Providing a text description when user provides information that is not in list of allowed values

Provide clear error messages for invalid input.

```html
<form>
  <label for="email">Email Address</label>
  <input type="email" id="email" name="email" required>
  <span class="error-message" id="email-error"></span>
  
  <button type="submit">Submit</button>
</form>

<script>
const form = document.querySelector('form');
const emailInput = document.getElementById('email');
const emailError = document.getElementById('email-error');

form.addEventListener('submit', (e) => {
  e.preventDefault();
  
  if (!emailInput.value.includes('@')) {
    emailError.textContent = 'Please enter a valid email address';
    emailInput.setAttribute('aria-invalid', 'true');
    emailInput.setAttribute('aria-describedby', 'email-error');
  }
});
</script>
```

**Related Criteria**: 3.3.1 Error Identification, 3.3.3 Error Suggestion

**Best Practices:**
- Provide clear, specific error messages
- Associate errors with form fields using `aria-describedby`
- Use `aria-invalid` to indicate invalid fields
- Provide suggestions for correcting errors
- Validate in real-time when possible

## Fieldset and Legend

Group related form controls together.

```html
<fieldset>
  <legend>Contact Information</legend>
  
  <label for="name">Name</label>
  <input type="text" id="name" name="name">
  
  <label for="email">Email</label>
  <input type="email" id="email" name="email">
</fieldset>
```

**Best Practices:**
- Use `<fieldset>` to group related controls
- Use `<legend>` to describe the group
- Nest fieldsets appropriately
- Don't use fieldset for single controls

## Form Controls

Use appropriate form control elements for different input types.

```html
<!-- Text input -->
<input type="text" name="username" id="username">

<!-- Email input -->
<input type="email" name="email" id="email">

<!-- Password input -->
<input type="password" name="password" id="password">

<!-- Checkbox -->
<label>
  <input type="checkbox" name="subscribe" id="subscribe">
  Subscribe to newsletter
</label>

<!-- Radio buttons -->
<fieldset>
  <legend>Choose your preference:</legend>
  <label>
    <input type="radio" name="preference" value="option1">
    Option 1
  </label>
  <label>
    <input type="radio" name="preference" value="option2">
    Option 2
  </label>
</fieldset>

<!-- Select dropdown -->
<label for="country">Country:</label>
<select name="country" id="country">
  <option value="us">United States</option>
  <option value="ca">Canada</option>
  <option value="uk">United Kingdom</option>
</select>

<!-- Textarea -->
<label for="message">Message:</label>
<textarea name="message" id="message" rows="4" cols="50"></textarea>
```

**Best Practices:**
- Use appropriate input types for data (email, tel, url, etc.)
- Provide autocomplete attributes when helpful
- Use `placeholder` for format hints, not as labels
- Set appropriate `min`, `max`, `step` values for numeric inputs

## Common Mistakes

### 1. Using Placeholder Text as Labels

```html
<!-- Bad: Placeholder as label -->
<input type="email" placeholder="Email Address">

<!-- Good: Proper label -->
<label for="email">Email Address</label>
<input type="email" id="email">
```

### 2. Missing Required Indicators

```html
<!-- Bad: No required indicator -->
<label for="email">Email Address</label>
<input type="email" id="email">

<!-- Good: Required indicator -->
<label for="email">Email Address *</label>
<input type="email" id="email" required aria-required="true">
```

### 3. Unclear Error Messages

```html
<!-- Bad: Generic error message -->
<span class="error">Invalid input</span>

<!-- Good: Specific error message -->
<span class="error">Please enter a valid email address</span>
```

### 4. Not Associating Labels with Inputs

```html
<!-- Bad: No association -->
<label>Email Address</label>
<input type="email">

<!-- Good: Proper association -->
<label for="email">Email Address</label>
<input type="email" id="email">
```

## Testing Checklist

- [ ] All form controls have associated labels
- [ ] Required fields are clearly marked
- [ ] Error messages are clear and specific
- [ ] Form can be completed using keyboard
- [ ] Form validation provides helpful feedback
- [ ] Fieldsets are used for related groups
- [ ] Appropriate input types are used
