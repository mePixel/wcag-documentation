## Success Criteria Overview

WCAG 2.2 includes 87 success criteria across the four principles:

| Principle | Level A | Level AA | Level AAA | Total |
|-----------|---------|----------|-----------|-------|
| Perceivable | 7 | 8 | 6 | 21 |
| Operable | 13 | 9 | 8 | 30 |
| Understandable | 5 | 7 | 6 | 18 |
| Robust | 1 | 1 | 0 | 2 |
| **Total** | **26** | **25** | **20** | **87** |

**Note**: This documentation focuses on Level AAA criteria, the highest level of web accessibility conformance, covering all A, AA, and AAA success criteria in WCAG 2.2.

## New in WCAG 2.2

WCAG 2.2 introduced several new success criteria and removed one from WCAG 2.1:

- **2.4.11 Focus Not Obscured (AA)** — Focus indicator must not be hidden by sticky headers or other content
- **2.4.12 Focus Appearance (AAA)** — Focus indicator must be at least 2px solid with 3:1 contrast and 1px offset from the focused element
- **2.4.13 Focus Appearance Minimum (AA)** — A focus indicator must exist with sufficient contrast against the background
- **2.5.7 Dragging Movements (AA)** — Provide an alternative to dragging for all functionality that uses a dragging movement
- **2.5.8 Target Size Minimum (AA)** — Interactive elements must be at least 24×24 CSS pixels
- **2.5.8 Target Size (AAA)** — Interactive elements must be at least 44×44 CSS pixels
- **3.2.6 Consistent Help (A)** — Help mechanism must be available in a consistent location across pages
- **3.3.7 Redundant Entry (A)** — Previously entered data must be auto-populated to avoid re-entry
- **3.3.8 Accessible Authentication (AAA)** — Authentication must not require cognitive function tests, with no exceptions
- **2.2.6 Timeouts (AAA)** — Users must be warned at least 20 seconds before a session timeout

> **Removed**: SC 4.1.1 Parsing was removed in WCAG 2.2, as modern browsers and assistive technologies no longer require it.

## Techniques Overview

WCAG techniques provide specific methods for meeting success criteria:

- **Sufficient Techniques**: Methods that are sufficient for meeting a success criterion
- **Advisory Techniques**: Additional methods that can enhance accessibility
- **Failures**: Common mistakes that cause a success criterion to fail
- **Common Failures**: Frequently occurring failures to avoid

## Quick Reference

### Perceivable (1.x)

- **1.1 Text Alternatives**: Non-text content has text alternatives
- **1.2 Time-based Media**: Alternatives for audio and video
- **1.3 Adaptable**: Content can be presented in different ways
- **1.4 Distinguishable**: Content is easier to see and hear

### Operable (2.x)

- **2.1 Keyboard Accessible**: All functionality available via keyboard
- **2.2 Enough Time**: Users have enough time to read and use content
- **2.3 Seizures**: Content does not cause seizures
- **2.4 Navigable**: Users can navigate and find content
- **2.5 Input Modalities**: Functions can be operated with different input devices

### Understandable (3.x)

- **3.1 Readable**: Text is readable and understandable
- **3.2 Predictable**: Web pages appear and operate in predictable ways
- **3.3 Input Assistance**: Users are helped to avoid and correct mistakes

### Robust (4.x)

- **4.1 Compatible**: Content is compatible with current and future user agents
