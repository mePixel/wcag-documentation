# Accessible Tables

Data tables present information in rows and columns. When built accessibly, screen readers can navigate cell by cell, announce column and row headers, and convey the full meaning of the data. Without proper markup, tables become incomprehensible to users who cannot see the visual layout.

## Overview

Accessible tables use semantic HTML elements to establish clear relationships between data cells and their headers. Simple tables need basic `<th>` elements, while complex tables with merged cells or multi-level headers require additional attributes like `scope`, `headers`, and `id` to maintain those associations.

### Table Types

- **Simple data tables**: Single row or column of headers
- **Complex data tables**: Multiple header levels, merged cells, or spanned headers
- **Layout tables**: Using tables for visual layout (avoid — use CSS instead)

## WCAG Requirements

### Perceivable
- **1.3.1 Info and Relationships**: Table headers and data cell relationships must be programmatically determinable
- **1.3.2 Meaningful Sequence**: The reading order of table content must be logical and predictable

### Understandable
- **2.4.6 Headings and Labels**: Table headers and captions must describe the content clearly

## Implementation Patterns

### Simple Data Table with Headers

Use `<th>` for header cells and `<td>` for data cells. The `<th>` element automatically associates with cells in its column or row.

```html
<table>
  <caption>Employee Directory</caption>
  <thead>
    <tr>
      <th scope="col">Name</th>
      <th scope="col">Department</th>
      <th scope="col">Email</th>
      <th scope="col">Start Date</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Jane Smith</td>
      <td>Engineering</td>
      <td>jane@example.com</td>
      <td>2022-03-15</td>
    </tr>
    <tr>
      <td>John Doe</td>
      <td>Design</td>
      <td>john@example.com</td>
      <td>2023-01-10</td>
    </tr>
    <tr>
      <td>Alice Johnson</td>
      <td>Marketing</td>
      <td>alice@example.com</td>
      <td>2021-07-22</td>
    </tr>
  </tbody>
</table>
```

### Table with Caption

Every data table should have a `<caption>` element that describes the table's purpose or content. The caption is announced by screen readers before the table content.

```html
<table>
  <caption>
    Quarterly Revenue Report for 2024 (in thousands of USD)
  </caption>
  <thead>
    <tr>
      <th scope="col">Quarter</th>
      <th scope="col">Revenue</th>
      <th scope="col">Expenses</th>
      <th scope="col">Profit</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Q1 2024</td>
      <td>$1,200</td>
      <td>$800</td>
      <td>$400</td>
    </tr>
    <tr>
      <td>Q2 2024</td>
      <td>$1,500</td>
      <td>$900</td>
      <td>$600</td>
    </tr>
    <tr>
      <td>Q3 2024</td>
      <td>$1,300</td>
      <td>$850</td>
      <td>$450</td>
    </tr>
    <tr>
      <td>Q4 2024</td>
      <td>$1,800</td>
      <td>$950</td>
      <td>$850</td>
    </tr>
  </tbody>
</table>
```

### Table with Scope Attribute

The `scope` attribute explicitly tells screen readers whether a `<th>` is a column header or row header. While often inferred, explicitly declaring `scope` improves clarity.

```html
<table>
  <caption>Student Grades by Subject</caption>
  <thead>
    <tr>
      <th scope="col">Student</th>
      <th scope="col">Mathematics</th>
      <th scope="col">Science</th>
      <th scope="col">English</th>
      <th scope="col">Average</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">Alice</th>
      <td>92</td>
      <td>88</td>
      <td>95</td>
      <td>91.7</td>
    </tr>
    <tr>
      <th scope="row">Bob</th>
      <td>85</td>
      <td>91</td>
      <td>78</td>
      <td>84.7</td>
    </tr>
    <tr>
      <th scope="row">Carol</th>
      <td>97</td>
      <td>94</td>
      <td>90</td>
      <td>93.7</td>
    </tr>
  </tbody>
</table>
```

### Complex Table with Headers/ID Associations

When tables have multi-level headers or cells that span multiple rows or columns, use `id` and `headers` attributes to explicitly associate data cells with their headers.

```html
<table>
  <caption>Monthly Sales by Region and Product Category</caption>
  <thead>
    <tr>
      <th rowspan="2" scope="col" id="region">Region</th>
      <th colspan="3" scope="colgroup" id="electronics">Electronics</th>
      <th colspan="3" scope="colgroup" id="clothing">Clothing</th>
    </tr>
    <tr>
      <th scope="col" id="elec-phones" headers="electronics">Phones</th>
      <th scope="col" id="elec-laptops" headers="electronics">Laptops</th>
      <th scope="col" id="elec-tablets" headers="electronics">Tablets</th>
      <th scope="col" id="cloth-men" headers="clothing">Men's</th>
      <th scope="col" id="cloth-women" headers="clothing">Women's</th>
      <th scope="col" id="cloth-kids" headers="clothing">Kids'</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row" id="north">North America</th>
      <td headers="electronics elec-phones north">$2.1M</td>
      <td headers="electronics elec-laptops north">$1.8M</td>
      <td headers="electronics elec-tablets north">$0.9M</td>
      <td headers="clothing cloth-men north">$1.2M</td>
      <td headers="clothing cloth-women north">$1.5M</td>
      <td headers="clothing cloth-kids north">$0.7M</td>
    </tr>
    <tr>
      <th scope="row" id="europe">Europe</th>
      <td headers="electronics elec-phones europe">$1.7M</td>
      <td headers="electronics elec-laptops europe">$1.4M</td>
      <td headers="electronics elec-tablets europe">$0.6M</td>
      <td headers="clothing cloth-men europe">$0.9M</td>
      <td headers="clothing cloth-women europe">$1.1M</td>
      <td headers="clothing cloth-kids europe">$0.5M</td>
    </tr>
    <tr>
      <th scope="row" id="asia">Asia Pacific</th>
      <td headers="electronics elec-phones asia">$3.2M</td>
      <td headers="electronics elec-laptops asia">$2.5M</td>
      <td headers="electronics elec-tablets asia">$1.8M</td>
      <td headers="clothing cloth-men asia">$1.6M</td>
      <td headers="clothing cloth-women asia">$2.0M</td>
      <td headers="clothing cloth-kids asia">$0.9M</td>
    </tr>
  </tbody>
</table>
```

### Responsive Table Pattern

Tables can be difficult to read on small screens. Use a responsive pattern that maintains accessibility across devices.

```html
<!-- Pattern 1: Horizontal scroll with accessible label -->
<div class="table-wrapper" role="region" aria-label="Scrollable data table" tabindex="0">
  <table>
    <caption>Product Comparison</caption>
    <thead>
      <tr>
        <th scope="col">Feature</th>
        <th scope="col">Basic Plan</th>
        <th scope="col">Pro Plan</th>
        <th scope="col">Enterprise Plan</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <th scope="row">Storage</th>
        <td>5 GB</td>
        <td>50 GB</td>
        <td>Unlimited</td>
      </tr>
      <tr>
        <th scope="row">Users</th>
        <td>1</td>
        <td>10</td>
        <td>Unlimited</td>
      </tr>
      <tr>
        <th scope="row">Support</th>
        <td>Email</td>
        <td>Priority email</td>
        <td>24/7 phone</td>
      </tr>
    </tbody>
  </table>
</div>

<style>
  .table-wrapper {
    overflow-x: auto;
    -webkit-overflow-scrolling: touch;
  }
  .table-wrapper:focus {
    outline: 3px solid #005fcc;
    outline-offset: 2px;
  }
  table {
    min-width: 600px;
    border-collapse: collapse;
  }
  th, td {
    padding: 0.75rem;
    border: 1px solid #ddd;
    text-align: left;
  }
</style>
```

```html
<!-- Pattern 2: Stacked cards on mobile (CSS-only) -->
<style>
  @media (max-width: 600px) {
    .responsive-table thead {
      display: none;
    }
    .responsive-table tbody tr {
      display: block;
      margin-bottom: 1rem;
      border: 1px solid #ddd;
      border-radius: 4px;
      padding: 0.75rem;
    }
    .responsive-table tbody td {
      display: block;
      padding: 0.25rem 0;
    }
    .responsive-table tbody td::before {
      content: attr(data-label);
      font-weight: bold;
      display: block;
      margin-bottom: 0.25rem;
    }
  }
</style>

<table class="responsive-table">
  <caption>Team Members</caption>
  <thead>
    <tr>
      <th scope="col">Name</th>
      <th scope="col">Role</th>
      <th scope="col">Email</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td data-label="Name">Jane Smith</td>
      <td data-label="Role">Lead Developer</td>
      <td data-label="Email">jane@example.com</td>
    </tr>
    <tr>
      <td data-label="Name">John Doe</td>
      <td data-label="Role">Designer</td>
      <td data-label="Email">john@example.com</td>
    </tr>
  </tbody>
</table>
```

## Common Pitfalls

### 1. Using Tables for Layout

```html
<!-- Bad: Table used for page layout -->
<table>
  <tr>
    <td class="sidebar">Navigation links...</td>
    <td class="content">Main content...</td>
  </tr>
</table>

<!-- Good: Use CSS for layout -->
<div class="layout">
  <aside class="sidebar">Navigation links...</aside>
  <main class="content">Main content...</main>
</div>

<style>
  .layout {
    display: grid;
    grid-template-columns: 250px 1fr;
    gap: 1rem;
  }
</style>
```

### 2. Missing Header Cells

```html
<!-- Bad: No headers -->
<table>
  <tr>
    <td>Jane</td>
    <td>Engineering</td>
    <td>jane@example.com</td>
  </tr>
</table>

<!-- Good: Proper headers -->
<table>
  <thead>
    <tr>
      <th scope="col">Name</th>
      <th scope="col">Department</th>
      <th scope="col">Email</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Jane</td>
      <td>Engineering</td>
      <td>jane@example.com</td>
    </tr>
  </tbody>
</table>
```

### 3. Missing Caption

```html
<!-- Bad: No caption -->
<table>
  <thead>
    <tr>
      <th scope="col">Product</th>
      <th scope="col">Price</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Widget</td>
      <td>$9.99</td>
    </tr>
  </tbody>
</table>

<!-- Good: With caption -->
<table>
  <caption>Product Pricing — Spring 2024 Catalog</caption>
  <thead>
    <tr>
      <th scope="col">Product</th>
      <th scope="col">Price</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Widget</td>
      <td>$9.99</td>
    </tr>
  </tbody>
</table>
```

### 4. Merged Cells Without Proper Associations

```html
<!-- Bad: Colspan/rowspan without headers/id -->
<table>
  <tr>
    <td colspan="3">Electronics</td>
  </tr>
  <tr>
    <td>Phones</td>
    <td>Laptops</td>
    <td>Tablets</td>
  </tr>
</table>

<!-- Good: Use headers/id for complex associations -->
<!-- See the "Complex Table with Headers/ID Associations" example above -->
```

### 5. Using Pre/Summary Instead of Caption

```html
<!-- Bad: Summary attribute is deprecated -->
<table summary="This table shows sales data">
  <tr><th>Product</th><th>Sales</th></tr>
</table>

<!-- Good: Use caption element -->
<table>
  <caption>Sales data by product category</caption>
  <tr><th>Product</th><th>Sales</th></tr>
</table>
```

## Testing Checklist

### Screen Reader Table Navigation
- [ ] Table is announced as a table with row and column counts
- [ ] Caption is announced before table content
- [ ] Column headers are announced when navigating between rows
- [ ] Row headers are announced when navigating between columns
- [ ] Complex header associations are correctly announced
- [ ] Table navigation shortcuts work (Ctrl+Alt+Arrow keys in NVDA)

### Header Association Verification
- [ ] All `<th>` elements have `scope` attributes in simple tables
- [ ] Complex tables use `id` and `headers` attributes correctly
- [ ] `colspan` and `rowspan` do not break header associations
- [ ] Every data cell can be traced back to its header(s)
- [ ] Header cells contain descriptive, meaningful text

### Caption Presence
- [ ] Every data table has a `<caption>` element
- [ ] Caption text clearly describes the table's content or purpose
- [ ] Caption is the first child of the `<table>` element
- [ ] Caption is visible (or available to screen readers if visually hidden)
- [ ] No deprecated `summary` attribute is used
