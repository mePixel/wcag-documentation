# Accessible Tabs

Tabs organize content into separate views where only one panel is visible at a time. When built accessibly, tabs allow users to navigate between sections using keyboard shortcuts and provide screen readers with clear information about which tab is active and what content is displayed.

## Overview

Accessible tabs use ARIA roles to communicate the relationship between tab labels and tab panels. The pattern requires a `tablist` container with `tab` elements that control corresponding `tabpanel` regions. Keyboard navigation follows the WAI-ARIA Authoring Practices pattern with arrow keys, Home, and End.

### Key Concepts

- **Tab list**: A container that holds a set of tab elements
- **Tab**: The control that activates a corresponding panel
- **Tab panel**: The content area associated with a tab
- **Activation model**: Whether selecting a tab activates it immediately (automatic) or requires an additional action (manual)

## WCAG Requirements

### Perceivable
- **1.3.1 Info and Relationships**: The relationship between tabs and their panels must be programmatically determinable

### Operable
- **2.1.1 Keyboard**: All tabs must be operable via keyboard using arrow keys
- **2.4.1 Bypass Blocks**: Tabs can help organize content into manageable sections

### Robust
- **4.1.2 Name, Role, Value**: Tabs must expose their role, selected state, and control relationships to assistive technologies

## Implementation Patterns

### Basic Tabs with ARIA

The foundation of accessible tabs uses `role="tablist"`, `role="tab"`, and `role="tabpanel"` with proper ARIA attributes linking them together.

```html
<div class="tabs">
  <div role="tablist" aria-label="Account settings" aria-orientation="horizontal">
    <button 
      role="tab" 
      id="tab-profile" 
      aria-selected="true" 
      aria-controls="panel-profile"
      tabindex="0"
    >
      Profile
    </button>
    <button 
      role="tab" 
      id="tab-security" 
      aria-selected="false" 
      aria-controls="panel-security"
      tabindex="-1"
    >
      Security
    </button>
    <button 
      role="tab" 
      id="tab-notifications" 
      aria-selected="false" 
      aria-controls="panel-notifications"
      tabindex="-1"
    >
      Notifications
    </button>
  </div>

  <div 
    role="tabpanel" 
    id="panel-profile" 
    aria-labelledby="tab-profile"
    tabindex="0"
  >
    <h3>Profile Settings</h3>
    <p>Manage your public profile information and display preferences.</p>
    <!-- Profile form content -->
  </div>

  <div 
    role="tabpanel" 
    id="panel-security" 
    aria-labelledby="tab-security"
    tabindex="0"
    hidden
  >
    <h3>Security Settings</h3>
    <p>Update your password and two-factor authentication settings.</p>
    <!-- Security form content -->
  </div>

  <div 
    role="tabpanel" 
    id="panel-notifications" 
    aria-labelledby="tab-notifications"
    tabindex="0"
    hidden
  >
    <h3>Notification Preferences</h3>
    <p>Choose which notifications you receive and how they are delivered.</p>
    <!-- Notification preferences content -->
  </div>
</div>
```

### Horizontal Tabs with Keyboard Navigation

Keyboard navigation follows the WAI-ARIA tabs pattern: arrow keys move between tabs, Home/End jump to the first/last tab, and the active tab is the only one in the tab order.

```javascript
function initTabs(tablist) {
  const tabs = Array.from(tablist.querySelectorAll('[role="tab"]'));

  tabs.forEach((tab) => {
    tab.addEventListener('click', () => {
      activateTab(tab, tabs);
    });

    tab.addEventListener('keydown', (e) => {
      const currentIndex = tabs.indexOf(tab);
      let newIndex;

      switch (e.key) {
        case 'ArrowRight':
          e.preventDefault();
          newIndex = (currentIndex + 1) % tabs.length;
          activateTab(tabs[newIndex], tabs);
          tabs[newIndex].focus();
          break;

        case 'ArrowLeft':
          e.preventDefault();
          newIndex = (currentIndex - 1 + tabs.length) % tabs.length;
          activateTab(tabs[newIndex], tabs);
          tabs[newIndex].focus();
          break;

        case 'Home':
          e.preventDefault();
          activateTab(tabs[0], tabs);
          tabs[0].focus();
          break;

        case 'End':
          e.preventDefault();
          activateTab(tabs[tabs.length - 1], tabs);
          tabs[tabs.length - 1].focus();
          break;
      }
    });
  });
}

function activateTab(selectedTab, allTabs) {
  // Deactivate all tabs
  allTabs.forEach((tab) => {
    tab.setAttribute('aria-selected', 'false');
    tab.setAttribute('tabindex', '-1');
    const panelId = tab.getAttribute('aria-controls');
    document.getElementById(panelId).hidden = true;
  });

  // Activate the selected tab
  selectedTab.setAttribute('aria-selected', 'true');
  selectedTab.setAttribute('tabindex', '0');
  const panelId = selectedTab.getAttribute('aria-controls');
  document.getElementById(panelId).hidden = false;
}
```

### Vertical Tabs Pattern

For vertical tabs, arrow key mappings change: Up/Down arrows navigate between tabs instead of Left/Right. Set `aria-orientation="vertical"` to communicate this to assistive technologies.

```html

    role="tablist" 
    aria-label="Document sections" 
    aria-orientation="vertical"
    class="tab-list-vertical"
  >
    <button 
      role="tab" 
      id="tab-overview" 
      aria-selected="true" 
      aria-controls="panel-overview"
      tabindex="0"
    >
      Overview
    </button>
    <button 
      role="tab" 
      id="tab-details" 
      aria-selected="false" 
      aria-controls="panel-details"
      tabindex="-1"
    >
      Details
    </button>
    <button 
      role="tab" 
      id="tab-reviews" 
      aria-selected="false" 
      aria-controls="panel-reviews"

      Reviews

  </div>

  <div 
    role="tabpanel"
```

### Manual Activation Pattern

In the manual activation model, arrow keys move focus between tabs but do not activate them. The user must press Enter or Space to activate the focused tab. This is useful when switching tabs triggers expensive operations like data loading.

```javascript
function initManualTabs(tablist) {
  const tabs = Array.from(tablist.querySelectorAll('[role="tab"]'));

  tabs.forEach((tab) => {
    tab.addEventListener('keydown', (e) => {
      const currentIndex = tabs.indexOf(tab);
      let newIndex;

      switch (e.key) {
        case 'ArrowRight':
          e.preventDefault();
          newIndex = (currentIndex + 1) % tabs.length;
          tabs[newIndex].focus(); // Only move focus, don't activate
          break;

        case 'ArrowLeft':
          e.preventDefault();
          newIndex = (currentIndex - 1 + tabs.length) % tabs.length;
          tabs[newIndex].focus();
          break;

        case 'Home':
          e.preventDefault();
          tabs[0].focus();
          break;

        case 'End':
          e.preventDefault();
          tabs[tabs.length - 1].focus();
          break;

        case 'Enter':
        case ' ':
          e.preventDefault();
          activateTab(tab, tabs); // Activate on explicit action
          break;
      }
    });

    tab.addEventListener('click', () => {
      activateTab(tab, tabs);
    });
  });
}
```

## Common Pitfalls

### 1. Using `display: none` on Tab Panels

Some screen readers may skip panels hidden with `display: none`. Use the `hidden` attribute or visually hide panels while keeping them accessible.

```html
<!-- Bad: display:none may cause screen reader issues -->
<div role="tabpanel" id="panel-1" style="display: none">
  Content here
</div>

<!-- Good: Use the hidden attribute -->
<div role="tabpanel" id="panel-1" hidden>
  Content here
</div>

<!-- Also good: Visually hidden but still accessible -->
<style>
  .tabs [role="tabpanel"][hidden] {
    display: block;
    position: absolute;
    width: 1px;
    height: 1px;
    overflow: hidden;
    clip: rect(0 0 0 0);
  }
</style>
```

### 2. Missing `aria-selected` State

```html
<!-- Bad: No indication of which tab is active -->
<button role="tab" aria-controls="panel-1">Tab 1</button>
<button role="tab" aria-controls="panel-2">Tab 2</button>

<!-- Good: aria-selected clearly indicates the active tab -->
<button role="tab" aria-selected="true" aria-controls="panel-1">Tab 1</button>
<button role="tab" aria-selected="false" aria-controls="panel-2">Tab 2</button>
```

### 3. No Arrow Key Navigation

```html
<!-- Bad: Only Tab key navigates between tabs, requiring many keystrokes -->
<button role="tab">Tab 1</button>
<button role="tab">Tab 2</button>
<button role="tab">Tab 3</button>
<!-- Each tab is in the tab order (tabindex="0") -->

<!-- Good: Only active tab is in tab order; arrow keys navigate -->
<button role="tab" tabindex="0" aria-selected="true">Tab 1</button>
<button role="tab" tabindex="-1" aria-selected="false">Tab 2</button>
<button role="tab" tabindex="-1" aria-selected="false">Tab 3</button>
```

### 4. Using Links Instead of Buttons for Tabs

```html
<!-- Bad: Links imply navigation, not tab control -->
<a href="#panel-1" role="tab">Profile</a>
<a href="#panel-2" role="tab">Settings</a>

<!-- Good: Buttons are the correct element for tab controls -->
<button role="tab" aria-selected="true" aria-controls="panel-1">Profile</button>
<button role="tab" aria-selected="false" aria-controls="panel-2">Settings</button>
```

## Testing Checklist

### Keyboard Navigation
- [ ] Arrow Right/Left (or Up/Down for vertical) moves between tabs
- [ ] Home key focuses the first tab
- [ ] End key focuses the last tab
- [ ] Only the active tab is in the page tab order (tabindex="0")
- [ ] Tab key moves focus from the tab list into the active panel content
- [ ] Enter/Space activates a tab in manual activation mode

### Screen Reader Testing
- [ ] Screen reader announces the tab list with its label
- [ ] Each tab announces its position (e.g., "tab 1 of 3")
- [ ] The selected tab announces its selected state
- [ ] Tab panels announce their associated tab label
- [ ] Switching tabs is communicated to the screen reader

### Functional Testing
- [ ] Clicking a tab activates it and displays the correct panel
- [ ] Only one panel is visible at a time
- [ ] Tab content updates correctly when switching tabs
- [ ] Focus styles are clearly visible on tabs
